# 陆军观察与普通命令（旧桌面版归档）

> 本文记录退役时的实现和命令。当前入口见[工具目录](../../../tools/README.md)。

陆军通过真实存档中的本国军团 ID、成员 ID 和当前命令观察，由普通玩家界面下令。`goto_province` 仅供裁判移动镜头，移动／进攻使用普通右键；停止使用军团停止计划按钮及游戏 `unitview.gui` 中 `btn_hold` 的 H 快捷键。每个动作都在暂停时保存新存档，核验效果后才允许推进。

## 观察

国家观察中的 `army` 包含：

- 本国师 ID、位置、所属州、组织度、存档原始强度值、现有人力与需求人力、原始补给比例、当前路径与计划执行状态。原始强度、补给数据不被擅自解释成百分比。
- 本国军团 ID、名称、真实成员及已有计划类型。
- 共享公开 `war_relation` 确认的敌国、开战日、本国伤亡。引擎可能只在交战一方序列化关系；观察合并已选国家任一侧与解析器从未选国家投影的 `public_wars`，让防守方也能合法反击。端点或相同战争副本冲突时拒绝，不从负面态度或战争目标推断已开战；只投影本国伤亡，不向玩家提供敌方伤亡或其他私密状态。
- 本国师的上次交战日期，以及 `combat.land_combat` 中实际有本国师参与的战斗 ID、位置、攻守角色和本国参与者。敌方参与者 ID、兵力与损耗不会传给玩家；缺少整个 combat 块时明确标为未观察。
- 已校准军团的动作菜单，以及有限的真实省份候选。

控制权优先读取同一存档 `provinces.PROVINCE.controller`，没有省份覆盖值时回退到所属州的 `owner`。州的 `controller` 不能代替精确省份控制权：一个州可能被双方部分占领。早期 JSON 没有整个 `provinces` 字段时，移动和进攻候选关闭，等待新快照。

只向玩家提供本国部队，不从全局存档偷看敌军位置、数量或隐藏计划。当前模式仍属于项目的调试观察范围，尚未验收完整情报与战争迷雾。

## 动作合同

| 动作 | args | 含义 |
| --- | --- | --- |
| `army.move` | `army_id, target_province_id` | 经友军陆地路线移动到指定省份 |
| `army.attack` | `army_id, target_province_id, target_state_id` | 普通右键进攻已宣战敌国控制的省份，不会宣战 |
| `army.stop` | `army_id` | 停止既有计划执行并停止当前移动 |

省份与州 ID 必须从本轮候选原样选择。候选以安装地图像素邻接计算，要求每个成员都能通过受控陆地到达；陆路搜索最多 12 步，进攻只额外跨入相邻敌省。每个军团每回合至多收到一个动作，不能用不同动作 ID 对同一军团连续重排。

有效州脚本中的 `impassable=yes` 同时从目标和途中排除；存档没有保留该静态字段，不能只依赖存档判断。脚本来源不完整或无法解析的州标为未知，也不作为可通行路线。

先固定到已验收的省份缩放，再用相机命令定位。镜头到达目标后读取 debug tooltip 的精确 `Province ID`，选择军团后再核验一次。读不到目标身份时不发出右键。命令后的存档必须显示每个成员保持原位置、路径以请求省份结束并为普通 `player_order`，不得瞬移；其他师、其他玩家和经济状态必须保持不变。进攻命令交付成功与之后实际发生战斗分开记录。

军团进攻可能部分响应：已经在原地防御战中的师，可能无法接受新的进攻路径。只有该师前后整个对象不变、同一位置的同一防御战前后均有它参加，而且其他成员至少产生一条真实新路径时，才把它明确记为 `blocked_units`，并返回 `effect_status=partial`。其余响应者列在 `responded_units`；未知原因不被当作正常阻塞。`verified=true` 表示派发结果已核清，不能解释成全军团都执行了。

执行器在移动／进攻前会停止旧计划，核验只允许行动军团旧计划的 `can_execute:1` 变成缺省或 0；计划定义、路径、成员和其他军团必须不变。

视频与复盘应分别展示四层证据：命令已派发；全员或部分响应；推进后实际行军／到达；实际交战。实际交战需要本国师参与战斗的直接记录或新的交战日期，不能仅凭整个国家伤亡增加归因于某次命令。

## 首次绑定与校准

动作默认关闭。先在暂停且原生国家 AI 已受控的测试局中绑定军团，再为每种操作执行一次探针；同一已验收界面的其他绑定军团可以复用该操作，不需要逐军团重复校准。`configs/army.local.json` 保存本机绑定和现场证据，不应上传 GitHub。

从国家观察的 `army.armies` 找到军团 ID。绑定命令默认把其 UI 名称改为军团 ID 的数字文本，也可用 `--binding-name` 指定短名称；短数字对本机中文 OCR 更稳定。保存后确认真正改名的 ID、成员、命令和日期正确，才登记绑定。`card-x` 必须匹配当前截图中检测到的计数框；`card-index` 是原始计数框的序号，不能用未经核验的存档顺序代替。

也可使用 `bind-all --country ITA --known-disabled-pid CURRENT_PID --name UNIQUE_BULK_BIND_RUN`。它通过可见卡片的“点击选中”和真实军团说明识别军团，拒绝创建新军团、“+”及军团群卡片；只为真军团设置无重名的六位数字临时名称，随后一次新存档发现真实 ID 并核实只发生改名。未知卡片留在 `skipped_frames`，不会强点。重绑后重新确认实际 ID、名字和成员，原始逐军团调试证据只有在这些信息对应时保留。

`bind-all` 先扫描底栏，再扫描右侧战区列表的真实彩色军团盾牌行，后者可以选到被底栏军团群折叠隐藏的军团。每个候选点只先悬停，只有 tooltip 明确显示“点击选中”和真实军团说明才点击；军团群、创建按钮和未知悬停结果被跳过。差分裁框失败时只对同帧全图补读 OCR，没有军团 tooltip 的画面仍被拒绝。已绑定军团与本次刚改名的数字标记不会重复改名；后续执行也使用这条右侧选择路径并严格核对数字 header。

一次扫描覆盖当前可见的底栏及战区盾牌。结果的 `binding_coverage.unbound_army_ids` 明确列出仍未绑定的军团；`verified=true` 表示本次改名核验通过，不表示全国军团都在屏幕上。先把需要的战区滚到可见范围，再以唯一新运行名补绑；滚动本身不改变已有命令。军团数为零的国家需要先完成下面的准备操作。

### 准备没有军团的国家

裁判可使用 `create` 在普通界面把同一省份的未分配师编为新军团。它属于开局准备，不是模型决策动作：先读取精确省份及该省全部本国师 ID，确认都未归属任何军团，再框选该省部队，点击 tooltip 证明是“创建一个新的集团军，并编入已选中的陆军师”的卡片。军团群及未选中陆军师的禁用按钮被排除；创建按钮只点击一次。

```powershell
.venv/Scripts/python.exe tools/army_actions.py create `
  --country GER --province-id 11560 --division-ids 23,24,25,27,28,29 `
  --binding-name 990001 --box 64 48 `
  --known-disabled-pid CURRENT_PID --match-config EUROPE_MATCH_CONFIG `
  --name UNIQUE_GER_CREATE_RUN
```

这些 ID 来自本机实验局，换存档必须重读。`--box` 是省份缩放下选框半宽和半高。新存档必须只新增一个成员恰好符合请求的军团，所有师的完整对象、位置和路径不变，旧军团、日期、五国经济与部队、省份控制和州内容不变。核验通过才记录新军团 ID 并自动绑定数字名称；它随后复用同界面已验收的移动／停止／进攻能力。失败保留前后证据，不能直接重放创建命令。

需要把既有军团中的本省部队拆为独立军团时，显式加 `--from-army-id ID`。该省请求仍须包含全部本国师，而且它们都只能属于这个源军团，源军团必须留下其他成员。新增军团成员与源军团移出成员必须精确对应；原计划定义和师对象没有一般性豁免。如果游戏同步变更计划或单位状态导致首次核验失败，先分析已保存结果，不可重复创建。

```powershell
.venv/Scripts/python.exe tools/army_actions.py bind `
  --country ITA --army-id 192 --card-x 459 `
  --known-disabled-pid CURRENT_PID --name UNIQUE_BIND_RUN

.venv/Scripts/python.exe tools/army_actions.py probe `
  --country ITA --army-id 192 --action army.move --target-province-id 3776 `
  --known-disabled-pid CURRENT_PID --name UNIQUE_MOVE_RUN

.venv/Scripts/python.exe tools/army_actions.py probe `
  --country ITA --army-id 192 --action army.stop `
  --known-disabled-pid CURRENT_PID --name UNIQUE_STOP_RUN
```

上面的 ID、坐标和目的地是本机实验局的例子，其他存档必须重新读取。每个实验名唯一。自定义 3–5 国列表可传 `--match-config PATH`，操作国必须在列表中。

探针保存到 `runs/army/NAME/`。存档验证通过后，登记游戏 exe 哈希、渲染尺寸、OCR 语言、有效界面文件与字体集对应的 UI 操作验收。只有相同界面身份、真实证据状态和动作类型全部匹配时，已绑定军团才共享该操作；构建、布局、字体、语言或渲染尺寸变化后关闭旧验收。失败会以非零退出码返回并保留前后存档和错误记录，不能直接重放。

选择已绑定军团时，只试选 tooltip 证明确实存在的军团卡片，并在裁去数量图标的局部区域双尺度严格核对数字标题；不按相似名称下令。每次读取 tooltip 前实际移开鼠标清掉旧悬停。省份身份从同一截图全图读取，优先使用本机已有的 `en-US` OCR 对 ASCII `Province ID` 字段进行双尺度识别；英文没有完整 ID 时才用严格中文结果。数字必须是完整 token，中文把末尾数字合成汉字时不能截取前半段；多个有效 ID 冲突时拒绝，也不会依照请求值挑选识别答案。`tdebug` 开关以控制台明确的 ENABLED/DISABLED 回复确认，不因单位计数遮挡就盲目关闭。

陆军选择、创建及绑定入口显式切回 F1 陆军模式，允许海军 F2／空军 F3 动作之后继续交错执行。右侧盾牌的训练图标遮住悬停身份时，仅对失败点向下六像素补读一次；没有真实军团说明仍不点击。

已有战争的进攻探针使用 `--action army.attack --target-province-id ID`；CLI 会从安装地图补齐州 ID。没有宣战关系、不是敌控制省份、全军团无有效友方陆路时拒绝。进攻探针不会代替推进后的实际交战验收。

## 恢复与适用范围

恢复已应用的移动命令时，允许路径仍在执行或部队已经自然到达目标。已知阻塞的防守师仍参加同一地点、同一防御战时，继续记录为防守结果，不假装它已收到进攻路径。进攻进入战斗后，带有本回合实际战斗日期的撤退可以被识别为战斗结果；成员自然损失需要该师原本参战的直接记录以及新增伤亡等证据，不被当成要重新下单的 UI 失败。证据不足时停止检查，原命令不会自动重放。

本模块不支持模型即时新建／调编军团、前线绘制、海运／登陆、空海军指令；军团创建仅用于裁判开局准备，宣战由独立外交执行器处理。原版地图与当前已安装界面是本阶段适配目标。检测到社区地图替换 `provinces.bmp` 或 `definition.csv` 时关闭地图目标，必须另行验收该地图投影后再启用，不能拿原版坐标操作新地图。
