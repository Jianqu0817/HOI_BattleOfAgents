# 从 AI 对局到视频成片

当前视频工作流以原生五国对局 GER/FRA/ITA/AUS/SWI 为基础。已完成29/50回合；离线审计为22,349通过、0失败、4 unknown。对局未到50回合冻结终点，第30回合尚未提交，不能称为50回合完成。证据包与范围见[2026-11-09制作验收](PRODUCTION_REVIEW_20261109.md)。

流程可展示事前意图、公开与私信表态、密封命令及执行结果、回合后的实际状态；旧运行缺少意图摘要时，只展示实际留存的提交理由。私密意图是结果发生前提交的简短决策摘要，不是隐藏思维链。宣战和海空军任务设置已有独立验收，但任务设置不代表战果。事件验证限于 `news.66`：第9回合安全暂停、选择并确认 resolved 后关窗，再恢复剩余12小时；其他通用事件或弹窗未验证。

## 1．开始录制前

OBS 原生 game_capture 已验证：1280×720、30fps、约2秒暂停画面，无音轨；portable `IRON_VERIFY` 配置已保存并正常退出。该短片只证明暂停画面捕获，不是29回合实录，也未验证长录制稳定性或游戏音轨。正式录制前仍需按实际节目配置试拍。录屏存独立目录，不放入 Git。

原始录制建议使用 MKV，结束后可用 OBS 的“录像转封装”生成剪辑软件接受的 MP4。保持原片，另外制作剪辑副本。若使用窗口／显示器捕获，录制范围应只覆盖游戏或回看页，避免将配置终端和密钥录入过程摄入。

给每场比赛记录一张场记卡：比赛名、模型与版本、国家和人设、胜负规则、日期、游戏版本、地图和 Mod。正式拍摄时先固定这些条件；需要比较模型能力时，安排国家或人设轮换。

## 2．对局中怎样留下可剪的材料

每轮按“观察 → 意图摘要 → 公开沟通 → 定向私信与回复 → 密封决策 → 裁判审查 → 游戏执行 → 结果”保存。原话不改写；想做更顺口的旁白，另记旁白文本。

OBS 持续录制即可。录屏开头拍下系统时钟和本次 run ID，作为真实 UTC 与录像时间码的对齐锚点。每轮开始、五国命令提交完成、开始推进和推进结束时，记录录屏中的时间位置及当前回合号。可以口述一声“第 N 回合，开始推进”，也可在纸上或剪辑笔记中记下时间。项目导出的 SRT 使用建议剪辑时间，尚未与 OBS 录屏自动同步；这些场记负责把数据记录对齐原片。

游戏执行器会保留操作截图与存档核验。某个动作若没有成功，应按执行记录处理：界面错误但存档确认生效，与存档未确认、玩家主动取消，是不同情况。剪辑时保留足够上下文，不能把执行器故障算作 AI 故意违约。宣战与陆海空任务设置已有独立验收；不要由任务回执推断战斗结果。

宣战素材分开显示密封请求、界面执行和已确认战争状态。只有前后存档确认新战争关系时，才展示“宣战生效”，并标明宣战方、被宣战方及实际新增参战关系。同轮对已经交战的对象再次提出宣战，会显示“已交战，未重复发送”，不能剪成第二次宣战。未生效或结果不明的适配器尝试不当作玩家反悔。

海空任务区分“已设置”和“已发生战斗”：联队获得制空或支援任务、舰队收到巡逻或移动命令，不等于已经取得战果。实战画面和战斗记录另作证据；没有舰队的内陆国家不会因节目需要而被标成具有海军。海空校准入口见[海空军说明](NAVAL_AIR.md)。

## 3．导出一个回合的观众素材包

完成回合后运行：

```powershell
.venv/Scripts/python.exe tools/episode.py export `
  --trial runs/deepseek_campaign_3 `
  --turn runs/turns/deepseek_campaign_turn3 `
  --output runs/video_preview/turn3
```

双击输出目录的 `index.html`，无需服务器或联网。页面可以按国家筛选、逐条揭示、隐藏／显示私密记录，并对照来源和截图。它是 **audience_full 全知观众包**，包括所有私信、私密意图及命令；不要交给参赛 Agent，也不要把整个文件夹直接塞入玩家记忆。

| 文件 | 用法 |
| --- | --- |
| `index.html` | 离线看全局故事，也可浏览器捕获为卡片画面 |
| `episode.json` | 紧凑事件、承诺账本、截图索引、来源文件与哈希 |
| `timeline.csv` | Excel／剪辑笔记中的筛选表，含建议时间、国家、原话和来源 |
| `timeline.jsonl` | 后续制作脚本可逐条读取的时间线 |
| `recording_markers.csv` | 实际记录 UTC 与建议剪辑时间分列，供对齐录屏锚点；旧记录缺时戳时不猜测 |
| `subtitles.srt` | 可导入剪辑软件的中文字幕初稿 |
| `narration.md` | 原话、理由、事实与解说素材清单 |
| `shotlist.md` | 建议画面和证据编号，供挑选镜头 |
| `assets/`、`assets.json` | 已复制到包内的界面截图，移动文件夹后仍能打开 |

大存档和完整观察 JSON 不复制进视频包。来源文件名、JSON 字段位置与内容哈希用于回到本机原始记录核对；保留原始 `runs` 及游戏存档作为制作归档。导出已有包只允许同一来源回合，不覆盖无关文件夹。`recording_markers.csv` 中的真实时戳来自模型记录、动作开始／结束和时钟检查，不能直接当成 OBS 时间码；旧素材没有这些字段时留空，不用文件修改时间代替。连续对局入口还会合并本轮 `production.jsonl` 阶段标记，保留 `campaign_turn`、阶段、UTC 和 epoch；`campaign_turn` 是本次录制的回合索引，接续旧游戏时可以与游戏 `turn_id` 不同。无法精确对应某条内容的阶段标记，其建议剪辑时间留空。

没有调用解说模型时，导出的是确定性记录概览，页面不会伪造 AI 吐槽。

## 4．生成独立解说

需要模型解说时，才在进程环境中设置好模型配置要求的密钥变量后运行以下命令：

```powershell
.venv/Scripts/python.exe tools/episode.py export `
  --trial runs/deepseek_campaign_3 `
  --turn runs/turns/deepseek_campaign_turn3 `
  --output runs/video_preview/turn3 `
  --model-config configs/model.example.json
```

也可只生成解说：

```powershell
.venv/Scripts/python.exe tools/episode.py commentary `
  --trial runs/deepseek_campaign_3 `
  --turn runs/turns/deepseek_campaign_turn3 `
  --model-config configs/model.example.json
```

解说保存在该 trial 的 `audience_commentary/`。原始调用记录保存模型、用量、提示词和响应，不保存认证请求头。相同证据和模型设置会复用已记录响应；证据或设置变化时拒绝误用旧解说。

解说分为事实摘录、策略判断、吐槽和精彩片段。事实摘录必须逐字引用已有事件，其他内容必须指向已存在的证据编号。策略判断和笑话仍需人工看一遍：引用存在不等于因果推断正确。原记录缺少“故意”的证据时，解说不能直接把失败叫作背叛。

这些全知解说只面向观众，不回流给玩家。各国的赛后学习另用 `tools/lessons.py` 生成：

```powershell
.venv/Scripts/python.exe tools/lessons.py --trial runs/deepseek_campaign_3 --turn runs/turns/deepseek_campaign_turn3 --model-config configs/model.example.json
```

每国仅收到本国观察、命令、执行与最终状态、公开讨论及本人参与的私信。`private_lessons/TAG.json` 保存最多三条带适用条件、置信度、分类和证据编号的经验；`private_lessons/evidence/TAG.json` 可核对引用；原始调用分别缓存。失败国家可以重试，成功国家复用原响应，不影响已保存的游戏回合。共享基础操作知识与私有对手判断应分开保存。

## 5．剪成一期有因果关系的故事

先看 `shotlist.md` 或离线页面，挑一到两条主要冲突。一个可直接尝试的结构是：

1. 开场先给一个关键结果或承诺，留下问题。
2. 交代本轮地图、各国目标和必要规则。
3. 播放公开表态及重要私信，不等量播放五国所有发言。
4. 揭示相关国家事前意图与密封命令，标清记录发生顺序。
5. 展示游戏地图、执行状态和后果，用原话回放形成对照。
6. 加入简短点评，再用下一轮的问题收尾。

字幕初稿覆盖全部记录，往往比成片长。导入 SRT 后按选定故事删减、移动，并对齐真实画面；不要直接将建议时间当作录屏中的时间码。中文专有名词、科技和国策 ID 可以在旁白里解释，但保留原始记录供核对。

可在视频中使用三种明确标注：“原话”“私密意图摘要”“旁白／解说判断”。配音若压缩或改写了原句，应归为旁白，不继续标作逐字原话。可以换配音、加头像和动作，不改造成 AI 实际没有说过或没有做过的事件。

## 6．交付与归档

成片、字幕、缩略图、回看包与原始数据分目录保存。发布前检查：角色和国家是否对应、私信发送对象是否正确、承诺期限和条件是否保留、动作是否真的执行、模型／地图／人设条件是否说明。节目奖项可以是“最佳预测”“最佳交易”“最大误判”，游戏胜负按预先公布规则计算。

GitHub 提交程序、模板和说明，不提交密钥、个人路径配置、原始存档、完整私聊运行记录、OBS 录像或外部依赖。若要公开一期观众包，请主动检查其中全部私密内容和来源素材，作为单独的节目发布物处理。
