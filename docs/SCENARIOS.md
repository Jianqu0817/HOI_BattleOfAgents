# 短局与社区地图

社区地图适合快速验证陆军、外交和角色互动，也可作为正式长局前的集训。项目目前没有已验收的通用社区地图名单；本文件提供选择和记录方法，不将未验证地图当成可直接运行的场景。替换地图若不能与当前地图索引匹配，应停止该场景的陆军操作和省份计分，不套用原版地图继续运行。

## 选择地图时检查什么

| 项目 | 验收方法 |
| --- | --- |
| 版本与依赖 | 记录游戏完整版本、地图 Mod 版本或提交、DLC、其他启用 Mod；确认能启动、载入和另存 |
| 参赛国家 | 3–5 个代码在该存档中实际存在，能切换且拥有可控制单位 |
| 接触机会 | 参赛国能在短局内发生竞争、谈判或支援，不长期被不可达海域隔开 |
| 起点条件 | 记录兵力、装备、工业、地形、补给和相邻关系；节目可采用非对称起点，但需说明 |
| 操作兼容 | 中文界面、窗口比例、部队身份、地图定位与目标识别能通过本机校准 |
| 持续命令 | 切换国家后部队命令保持，原生国家 AI 不接管；时间推进后存档验证一致 |
| 事件和补给 | 短时推进观察是否有阻塞事件、无法支撑的补给或持续空转 |
| 终点 | 预先明确停止回合数、对应游戏日期和需人工核对的胜负或展示指标 |

先在复制的存档上验证一个国家的一次普通命令和 24 小时推进，再扩展为全部参赛国一个回合。地图可正常加载，不代表该地图的单位选择、命令和终局检测已经适配。具体陆军可用目标取决于本机校准记录。

## 使用短局配置

项目提供 `configs/campaign.quick.example.json`：五国、3 回合、每轮 24 游戏小时、每国最多一个动作，节目功能开启。它用于验证流程，不会自动替换地图、生成兵力或建立战场。

```powershell
.venv/Scripts/python.exe tools/campaign.py run --name quick_pilot --config configs/campaign.quick.example.json --turns 1
```

按选定存档修改 `countries`，同时删除 `show.profiles` 和 `player_model_configs` 中不参赛的国家。国家代码必须来自该场景，不能把原版国家名当作社区地图一定存在的标签。

下面是三国参数示例；只有当前地图确实存在这些国家时才使用。其余字段保留示例配置，并将人设列表同步改成这三个国家：

```json
{
  "countries": ["GER", "ITA", "ENG"],
  "step_hours": 72,
  "turn_limit": 10,
  "action_limit": 1,
  "communication_rounds": 2
}
```

这表示每轮 3 游戏日、最多 10 回合，总推进 30 游戏日。若用五国、`step_hours=24`、`turn_limit=3`，则总推进 3 游戏日。`step_hours=360` 才是每轮 15 游戏日。日期按 HOI4 游戏日历计算，不将现实闰年规则套入。增减回合或改提示词应在开局前完成，恢复继续使用原冻结配置。

时间窗口需要配合场景：短时交火可用 24 小时或更短的战略回合；和平经营可以使用 72 或 360 小时。检查频率与决策频率不同，程序的时钟检查不意味着每次检查都会重新向模型询问。

## 固定终点与比赛目标

当前程序按 `turn_limit` 停止。`manifest.status=completed` 表示已完成配置的回合；冠军由开局时明确选择的 `scoring` 规则决定，不是从该状态字段推断。它不会自动识别社区地图的自定义胜利事件、原版投降或和平会议结果。

| `scoring.mode` | 终点计算 | 是否评冠军 |
| --- | --- | --- |
| `exhibition` | 展示各国指标，作为试播和操作验收 | 不评冠军，默认模式 |
| `territory_delta` | 终点控制陆地省份数减起点控制数 | 最高分获胜，同分并列 |
| `objectives` | 终点控制 `scoring.province_ids` 中指定陆地省份的数量 | 最高分获胜，同分并列 |

例如，开局前在比赛配置中加入 `"scoring": {"mode": "territory_delta"}`，即可采用省份净增量规则。目标模式还需填写真实目标陆地省份 ID 的整数数组 `province_ids`；应从当前场景的有效地图索引确认 ID，不使用未经核实的示例数字。

控制权先使用存档中的省份 controller 覆盖，再用该省份所在州的 owner 作为缺省。计分只计算当前安装地图中的陆地省份，不把海区算作领土。程序输出 `standings.json` 并在对局索引显示相应指标或排名。这是一套可复核的节目比赛规则，不代表完整的 HOI4 战争胜利条件。

开局前也可以另设人工核对的目标，例如保住首都、维持某条防线或比较其他目标完成情况。记录如何处理同盟胜利、个人目标、平局和技术中断。将规则写进 `show.common_rules_file`，同时保留给观众的场景卡；规则中的目标不会自动增加执行器尚未支持的动作。人工补充指标不要混入自动省份计分。

避免比赛进行到一半才按精彩程度改变目标或补发胜负分。节目可以另评最佳预测、最佳谈判、最大误判，与游戏结果分开。

```text
场景 ID：
录制日期与时区：
游戏完整版本：
地图名称、来源、版本／提交：
DLC 与启用 Mod 列表：
初始存档文件名与 SHA-256：
初始游戏日期：
参赛国家代码：
国家－模型－人设对应：
观察模式与尚未提供的数据：
已校准陆军／经营动作：
初始兵力、工业、地形和补给差异：
step_hours / turn_limit / action_limit：
预计结束游戏日期：
比赛目标与人工核对方法：
同盟、平局和技术中断处理：
是否带入集训经验、经验版本：

```

Windows 上可用 `Get-FileHash -Algorithm SHA256 -LiteralPath "实际初始存档.hoi4"` 记录存档哈希。不要在发布材料中携带密钥或本机用户名路径。

## 集训后带走什么

先把失败分为观察错误、执行错误、策略错误和外交判断，再让各国依据可见证据总结适用条件和置信度。程序将本国经验保存为 `private_lessons/<TAG>.json`，连续对局汇总到各自知识库。

正式局若要继承集训经验，可将本国经验整理到 `show.profiles.<TAG>.experience_file`。确保只放该国允许获知的内容，不把全知观众解说、他国秘密命令或私聊直接交给所有玩家。共同学到的操作方法另行整理进游戏指南，记录哪些知识对所有参赛者共同开放。
